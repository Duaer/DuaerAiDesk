# DuaerAiDesk

Release line: 0.15.x. Packages: <https://github.com/Duaer/DuaerAiDesk/releases/latest>. Chinese: [README.zh-CN.md](README.zh-CN.md).

DuaerAiDesk keeps one desk for a project change. The background typed at creation is the whole job. Duaer reads it a single time and picks a lane. Replies, chips, and the designer pass are left alone.

## Lanes

**Defect.** Something in the product already fails. The card stores the failure, the result that was due, and a way to repeat it. Tasks after that only repair. No diagram. No designer.

**New behavior.** The card states the goal, a check that can fail, and the baseline. Duaer then locks a diagram (a labeled route, a region, a side note). Style and layout land on the global card. The designer does not change project files. From there you split tasks, or you send the look back.

**Both.** The failure is filed before the new behavior. Repair task ids block the new tasks.

**Not yet clear.** Duaer asks one question. Still unclear, or the judge never answers: the lane is new behavior, and the project is still created.

## After the signature

Scope and acceptance are signed before dispatch. One to four employees can run together. The result can stay on the machine, go to GitHub Pages, or go to Cloudflare, Alibaba Cloud, or AWS when both keys are already saved.

The start control locks on click. The dispatch page keeps the progress. Another wave is issued only after this wave is stored finished and the chat is idle. A change throws away the signature and the lock, returns modules to draft, and asks for the diagram again.

DuaerAiDesk walks the lane. The judge only accepts or refuses a lock, and only names the lane of a new job. The coder takes one acceptance. The checker runs that acceptance. Publish is neither of those two, and it is not the designer.
