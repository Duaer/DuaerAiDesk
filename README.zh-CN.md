# DuaerAiDesk

版本线：0.15.x。安装包：<https://github.com/Duaer/DuaerAiDesk/releases/latest>。英文：[README.md](README.md)。

DuaerAiDesk 用一张 Duaer 台面接住项目里的一次改动。创建时写下的背景就是全部工作。Duaer 只读这一次，并选定一条路。之后的回复、选项和设计师那一轮不再重读。

## 四条路

**缺陷。** 产品里已有的东西坏了。卡片记下故障、应得的结果，以及再做一次的方法。后面的任务只修。没有图，也没有设计师。

**新行为。** 卡片写出目标、一条会失败的核对，以及基线。Duaer 再锁定一张图：标了名字的路线、一个分区、一条旁注。风格和布局落在全局卡上。设计师不动项目文件。然后可以拆任务，也可以把样子退回。

**两样都有。** 故障先入卡。修复任务的编号挡住新任务。

**还说不清。** Duaer 只问一句。仍然分不清，或判断没有回来：走新行为，项目照样能建。

## 签字之后

范围和验收签完才派工。一起干的人是 1 到 4 个。结果可以留在这台机器上，可以去 GitHub Pages，也可以在两把密钥已经保存时去 Cloudflare、阿里云或 AWS。

开始执行一点就锁。进度停在派工页。这一波已记成完成，并且对话空着，才发下一波。开变更会丢掉签字和锁，模块回到草稿，图要再锁一次。

DuaerAiDesk 自己走完这条路。判断师只决定能不能锁定，以及新工作属于哪一条。编码师领一条验收。核对跑这一条。发布不是这两个人的活，也不是设计师的活。
